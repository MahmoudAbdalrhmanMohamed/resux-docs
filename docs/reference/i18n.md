# i18n API (`resuxjs/i18n`)

`resuxjs/i18n` exports the optional Resux i18n module plus its public configuration/runtime helper types and composables.

::: info Source-aligned public surface
The package entry point imports several internal route/translation normalization helpers from `i18n/shared`, but it does **not** re-export those internal helpers from `resuxjs/i18n`. This reference documents only the public entry-point exports.
:::

## Imports

```ts
import i18nModule, {
  useI18n,
  useLocalePath,
  useSwitchLocalePath,
  defineI18nConfig,
  createI18nHeadEntry,
  type ResuxI18nLocaleInput,
  type ResuxI18nMessageSource,
  type ResuxI18nConfigInput,
  type ResuxI18nModuleOptions,
  type UseI18nResult
} from 'resuxjs/i18n'
```

## Configuration types

```ts
interface ResuxI18nLocaleInput {
  code: string
  name?: string
  dir?: 'ltr' | 'rtl'
}

type ResuxI18nMessageSource =
  | Record<string, unknown>
  | string
  | (() => unknown | Promise<unknown>)

interface ResuxI18nConfigInput {
  defaultLocale: string
  fallbackLocale?: string
  strategy?: ResuxI18nStrategy
  locales: ResuxI18nLocaleInput[]
  messages?: Record<string, ResuxI18nMessageSource>
  seo?: {
    hreflang?: boolean
  }
}

interface ResuxI18nModuleOptions
  extends Partial<ResuxI18nConfigInput> {}
```

`ResuxI18nStrategy` is used by the public config type and supports the route strategies documented in the [i18n guide](/guide/i18n): `prefix_except_default`, `prefix`, and `no_prefix`.

## Default module

The default export is a Resux module whose default strategy is `prefix_except_default`.

```ts
export default defineResuxConfig({
  modules: [
    ['resuxjs/i18n', {
      defaultLocale: 'en',
      fallbackLocale: 'en',
      locales: [
        { code: 'en', name: 'English', dir: 'ltr' },
        { code: 'ar', name: 'العربية', dir: 'rtl' }
      ],
      messages: {
        en: './locales/en.json',
        ar: () => import('./locales/ar.json')
      }
    }]
  ]
})
```

Module setup merges inline options with top-level `i18n` configuration, resolves message sources, normalizes runtime i18n config, writes it under public runtime config, and adds a `/` redirect to the default locale when strategy is `prefix`.

Message-load/import failures currently resolve that locale's catalog to `{}` rather than throwing a private filesystem/import stack into client-visible state.

## `defineI18nConfig()`

```ts
function defineI18nConfig<
  T extends ResuxI18nConfigInput
>(config: T): T
```

Typed identity helper for reusable i18n configuration:

```ts
import { defineI18nConfig } from 'resuxjs/i18n'

export const i18n = defineI18nConfig({
  defaultLocale: 'en',
  locales: [
    { code: 'en', dir: 'ltr' },
    { code: 'ar', dir: 'rtl' }
  ]
})
```

## `useI18n()`

```ts
function useI18n(): UseI18nResult
```

```ts
interface UseI18nResult {
  locale: ReturnType<typeof computed<string>>
  dir: ReturnType<typeof computed<'ltr' | 'rtl'>>
  locales: ResuxI18nLocale[]
  defaultLocale: string
  fallbackLocale: string
  strategy: ResuxI18nStrategy
  t: (
    key: string,
    params?: ResuxI18nTranslationParams
  ) => string
  tm: (key: string) => unknown
  resolveLocalized: (value: unknown) => string | null
  localePath: (
    to: string,
    localeCode?: string
  ) => string
  switchLocalePath: (
    localeCode: string,
    to?: string
  ) => string
  setLocale: (
    localeCode: string,
    to?: string
  ) => Promise<void> | void
}
```

Example:

```ts
const {
  locale,
  dir,
  t,
  tm,
  resolveLocalized,
  localePath,
  switchLocalePath,
  setLocale
} = useI18n()

const title = t('product.title', { name: 'Resux' })
const navigation = tm('navigation')
const greeting = resolveLocalized({ en: 'Hello', ar: 'مرحبا' })
const arabicAbout = localePath('/about', 'ar')
await setLocale('ar')
```

### Route/environment behavior

On the client, the current route comes from `location.pathname + search + hash`. Outside a browser, the composable reads the current path from the Resux app route when available and otherwise falls back to `/`.

`setLocale()` prefers the Resux client router when available; otherwise, in a browser, it falls back to `location.assign()`. On a server with no client router/window it returns without browser navigation.

### Fallback runtime config

If public runtime i18n config is unavailable, `useI18n()` falls back to an English `prefix_except_default` config with an empty English catalog. This keeps the helper callable, but it is not a substitute for enabling/configuring the i18n module.

## `useLocalePath()`

```ts
function useLocalePath(): (
  to: string,
  localeCode?: string
) => string
```

Returns the `localePath` function from `useI18n()`.

```ts
const localePath = useLocalePath()
const href = localePath('/account', 'ar')
```

## `useSwitchLocalePath()`

```ts
function useSwitchLocalePath(): (
  localeCode: string,
  to?: string
) => string
```

Returns the `switchLocalePath` function from `useI18n()`.

```ts
const switchLocalePath = useSwitchLocalePath()
const arabicCurrentPage = switchLocalePath('ar')
```

## `createI18nHeadEntry()`

```ts
function createI18nHeadEntry(
  routePath: string,
  routeOrigin?: string
): {
  htmlAttrs: Record<string, string>
  link: Array<Record<string, string>>
}
```

Builds i18n HTML/head metadata from current public runtime config.

```ts
const head = createI18nHeadEntry(
  '/about',
  'https://example.com'
)
```

When runtime i18n config is unavailable, it returns:

```ts
{
  htmlAttrs: { lang: 'en', dir: 'ltr' },
  link: []
}
```

Use the result with the framework's head integration rather than hand-assembling duplicate canonical/alternate entries.

## SSR, client navigation, and resumability

Translation/path calculations are ordinary Resux runtime logic and do not imply Vue hydration. Locale selection is derived from server/client route context; browser locale switching uses the Resux client router when available.

Message catalogs are placed into public runtime i18n config by module setup. Never put secrets into translation messages or public i18n configuration.
